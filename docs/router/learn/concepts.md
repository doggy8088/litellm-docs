# Router 概念 {#router-concepts}

{/* keep-version-note */}

`litellm.Router` 決定由哪個部署服務一個請求、執行呼叫，並處理呼叫失敗時發生的事。它在同一個模型
群組內重試、備援到其他模型群組，並將失敗的部署放入冷卻，使後續請求避開它們。proxy 會從它的設定
建立一個 Router，並將每個模型請求都送經它。SDK 使用者可以建立自己的 Router。

![呼叫者呼叫 litellm.Router，它挑選一個部署、呼叫提供者，並將冷卻、用量與失敗計數保存在路由快取中](../img/router-overview.svg)

對於每一個請求，router 負責回答一個問題：應該由哪個部署服務它。接著它必須處理該部署失敗時發生的事，
重試請求，並備援到其他部署。

這些文件其餘部分會參照幾個主要概念。本頁對它們做簡要概述。

![router 概念的順序：一個名稱解析為部署，存取規則、篩選器與策略為一次嘗試挑選一個，而失敗則進入重試、
備援與冷卻，它們寫入篩選器所讀取的共用狀態](../img/concepts-1.svg)

## 設定的內容 {#what-is-configured}

**部署**是一個可以服務模型的地方，例如某個區域中的 Azure OpenAI 資源，或 URL 背後的 vLLM 叢集。
它是 `model_list` 的一個項目，提供者呼叫的引數放在 `litellm_params` 中，中繼資料放在
`model_info` 中。它的 `model_info.id` 是其所有路由狀態的鍵。見[部署與模型群組](deployments_and_model_groups.md)。

**模型群組**是共用一個 `model_name` 的每一個部署。呼叫者要求的是模型群組，從不是部署。負載平衡、
重試與冷卻都發生在一個群組內，而備援會將請求在群組之間移動。

**名稱**是請求所要求的東西。它通常是一個模型群組，但也可以是一個別名、像 `openai/*` 這樣的萬用字元、
一個路由群組、某個團隊對模型的公開名稱，或一個部署 id。**解析**會將名稱轉換為可以服務該請求的部署
清單。見[名稱如何找到它的部署](names.md)。

## 誰可以使用什麼 {#who-may-use-what}

一個部署可以屬於一個**團隊**、在**存取時段**內為某些團隊保留、依 **PTU 份額**在團隊之間拆分，或
位於只有某些金鑰能到達的**存取群組**背後。這些規則在解析之後立即執行，並移除呼叫者不可使用的部署。
見[團隊與存取](teams_and_access.md)。

## 如何挑選一個部署 {#how-one-deployment-is-picked}

**篩選器**會移除目前不得服務這個請求的部署：未通過健康檢查的、正在冷卻的、被管理員封鎖的、對 prompt
來說太小的、缺少標籤的，或**順序**（較低的優先順序）高於另一個健康部署的。見[如何挑選一個部署](selection.md)。

**策略**會從其餘符合資格的部署中挑選一個。`simple-shuffle` 是預設值，會挑選一個加權隨機的部署。其他
策略依負載、延遲、用量或成本挑選。**路由群組**為一組模型群組提供它自己的策略，而像 auto router 這樣的
**子路由器**會在這一切執行之前，先決定請求要去哪個模型群組。見[策略、路由群組與子路由器](strategies.md)。

## 失敗時發生什麼 {#what-happens-on-failure}

**重試**會在同一個模型群組內再次執行挑選，因此可能落在不同的部署上。**備援**會在重試用盡後，將請求
移到另一個模型群組。**冷卻**會讓一個失敗的部署在幾秒內退出每一次挑選，而 **allowed fails** 決定這需要
多少次失敗。見[重試、備援與冷卻](reliability.md)。

## 狀態 {#state}

冷卻、失敗計數器與用量存放在一個**路由快取**中，它有一個記憶體層級與一個可選的 Redis 層級，因此一整個
proxy worker 機群共用同一份哪些部署是健康的檢視。見[proxy worker 之間的共用狀態](shared_state.md)。
